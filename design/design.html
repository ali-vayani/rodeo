All inputs: border: 1px solid #e0e0e0, padding: 8px 12px, font-family: inherit, font-size: 13px. On focus the border turns #191919. Full-width by default. Labels are 11px uppercase 600 with 6px gap below.

Hacker Portal
My Application
Route: /hacker/application — This page is entirely state-driven. The same URL shows a completely different UI depending on where the applicant is in the lifecycle. State is controlled by the backend — in the demo a tab bar switches between states for preview purposes.

Application States

Filling
Active form. User is still writing their application. Full editable form with three card sections (Personal Info, Short Answers, Logistics). Primary CTA is "Submit Application →". Secondary is "Save Draft". Auto-save timestamp shown in muted text.
Submitted
Read-only confirmation. Large ✓ mark, "Application Submitted" headline, summary box (name, email, role, school, submission date). No editable fields. Instruction to check back for updates.
Waitlisted
Waitlisted badge + position info. Shows waitlist position (#47) and approximate spots expected to open (~20–30). No user action required — passive informational state.
Accepted
Accepted badge. Celebratory headline. Event details card (date, location, RSVP deadline). Two buttons: "Confirm RSVP →" (primary) and "Can't attend" (ghost). This is the critical action state.
RSVP'd
RSVP Confirmed badge. Spot is locked. Shows confirmed details: name, role, school, and check-in code (e.g. RC-001 in DM Mono). Points user toward the My Account page for QR code and team setup.

Profile Card Details

Avatar is a 56×56px square (no border-radius) filled black with white initials (e.g. "AC"). Next to it: name at 16px 700, email at 12px muted, and a role badge. Below a rule: key-value rows for School, Grad Year, Status (badge), Check-in status.

Team Card Interactions

Type email → click "Add"
New member row appears in the list. Name is inferred from the email prefix (e.g. "jane.doe@..." → "Jane Doe"). "Add" button disables when team reaches 4 members.
Click "Remove" on a member
Member row disappears. Counter decrements. The current user's own row never shows a Remove button.
Team hits 4 members
"Add" button becomes disabled. "Team is full (max 4)." message appears below the form.

Team Member Row Structure

Each row: 32×32px avatar square (black for self, gray border for others) + name + email (truncated with ellipsis if long) + optional Remove button. Counter label above the input shows "X/4 members · Invite by email".

QR Code Card

In production this renders a real QR code image generated from the participant's unique check-in code. Beneath it: the code itself in DM Mono 13px 600, a subtitle with the check-in date, and a "Download PDF" ghost button. The code format is RC-XXX.

Admin Portal
Custom Email
Route: /admin/custom-email — A 3-step wizard for composing and sending a one-off bulk email to a filtered segment of attendees. Steps are shown as a horizontal stepper at the top. Completed steps can be navigated back to.

Step Flow

01
Filter Recipients
Choose who receives the email by status and role
02
Compose
Write the subject line and body
03
Confirm & Send
Review and send

Step 1 — Filter Recipients

Two cards: Status (checkboxes: accepted, waitlisted, rejected, pending — each showing its count) and Role (checkboxes: Hacker, Mentor, Judge, Volunteer). Below both cards: "[N] recipients selected" count updates live as boxes are checked. "Next: Compose →" is disabled if recipient count is 0.

Step 2 — Compose

Single card with Subject (text input) and Body (textarea, 10 rows). Available variable hint below the textarea. "Next: Review →" is disabled until both subject and body have content. "← Back" returns to Step 1 without losing filter selections.

Step 3 — Confirm & Send

Summary card: Recipients count, subject line, then a full rendered preview of the body with variables substituted. Two buttons: "← Back" and "Send to [N] recipients →". After clicking send, the page transitions to a full-page success state.

Post-Send State

Replaces the entire step flow. Centered card with a ✓ mark, "Email Sent", and "Your email was sent to N recipients." A "Send Another" secondary button resets the entire flow back to Step 1 with a cleared form.

Stepper Navigation

Current step shows black background and bold text. Completed steps (index less than current) are clickable and return to that step without losing data. Future steps are not clickable.

Event Row Structure

Three-column grid inside each row: time (100px, DM Mono 12px muted), content area (flex 1), delete button (right-aligned). Content area: title (14px 600) + location (12px muted) + type tag (10px DM Mono, mono-styled, bordered).

Event Types

logistics · ceremony · hacking · workshop · mentoring · judging. Each type has an associated display style in the tag; all are black/gray text with a 1px solid var(--border) tag border.

Interactions

Click "Day 1" or "Day 2"
Event list switches entirely. Active day button is black (primary style), inactive is ghost. The add form (if open) creates events for the currently active day.
Add event
New event inserted into the correct day's list, sorted by time string (ascending alphabetical sort — works for 12-hour time format).
Click "Delete" on an event
Event removed from that day's list only.
Admin Portal
Blacklist
Route: /admin/blacklist — Block specific emails or names from being able to apply. Two-column layout: add form + CSV import on the left (1fr), entry table on the right (2fr).

Add Entry Form

Fields: Email (email input, optional if name is filled), Name (text, optional), Reason (text, optional). "Add to Blacklist" button is disabled when both Email and Name are empty. On submit, a new row appears at the bottom of the table with today's date.

CSV Import Panel

A secondary info card in the left column below the add form. Describes the expected CSV format (email, name, reason columns). "Choose File" button opens a file picker — in production this triggers parsing and bulk insert.
